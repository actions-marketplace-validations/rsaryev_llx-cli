# AGENTS.md

Instructions for AI coding agents working on this repository.

**ARCHITECTURE.md is binding: follow it strictly.** Read it before any change. It fixes the
layers and the crates of each, what may know what, and the rules by id (L, C, P, A,
K, W, R, S). Every new file goes where its layer says, in its crate's place. A change that
does not fit is redesigned, or ARCHITECTURE.md is changed first, in its own commit, with the
owner's agreement; an exception is never made in code. Cite the rule ids a change touches.

`llx` is an ultrafast, lightweight agent runtime: a minimal agent for the terminal, helpers on any model, and a decision step for scripts and CI. It has five tools: `bash` (commands run to their end: the model reads and searches with it and runs the checks, B1-B4), `apply_patch` (every file it adds, changes, deletes or moves, as a patch of free text, B5), `ask`, a question to the person that the app answers, `agents`, other agents it starts (each a session with a parent, run in parallel), and `jobs`, monitors and schedules. The tool set is deliberately minimal: no plugins, no MCP servers consumed, no skills, no extra tools. A new capability goes into one of these (as an `action`), or is left to the shell.

## Layout

Packages and three apps: the server (the composition root), the interface and the binary. Every dependency points inward (rules L1-L5 below).

- `packages/contracts`: ports only, no logic.
  - `chat.rs`: the chat-model port, with our own `Message` (`said`: the person's words, from which the providers' session and cache keys are hashed), `ToolCall`, `Request` (with the `deadline` the caller still wants an answer by, the conversation's own `effort`, taken where the model offers it: `Selection::or_at`, and its `task`: a `TaskId` the agent gives each task, never twice in a process, `TaskId::NONE` for a one-off request), `Completion` (its `Ending`: whole, or cut off at the output limit; its `thought`, the reasoning as text where the host gives it so), `Usage` and `Spend` (usages summed: the chat model's in a run, the decision model's in `llx decide`).
  - `catalog.rs`: what a provider offers: `ModelEntry` (an id, a name, the `Effort` levels it takes, its default; `Effort::wire_name`, the spelling both providers send) and `Selection`, a model with a level it takes (its fields are private: no other level can be put in).
  - `tool.rs`: the agent's tools: `ToolSpec` (a name, a description, its `Input`: arguments' JSON Schema, or the Lark grammar of a text tool), `ToolOutput { report, shown }` (`shown`: what only the person reads, an edit's diff, never sent to the model), `ToolError { Failed, Fatal }`; `Tool::salvage`, what of a call the output limit cut off is whole (B7: `None` by default, and the call is not run).
  - `advice.rs`: the advisor port (C9): `Task` (the goal, the conversation, where the task starts), `Review { Done, GoOn(line) }`, `Advisor` (`level`, asked only as a conversation's first task starts; `review`).
  - `gate.rs`: a tool asks before an effect: `Effect { tool, subject, summary, needs }` (`Needs { Sandbox, Open }`: whether it must leave its sandbox, B6), `Verdict { Allow, Workspace, ReadOnly, Deny(why) }` (`Workspace`: run where it can change only the workspace; `ReadOnly`: where it can change nothing), `Gate`, and `Open`.
  - `person.rs`: a tool asks the person: `Question` with its `Choice`s, `Answer`, `Reply { Answers, Nobody(why), Stopped }`, `Person`.
  - `model.rs`: the decision-model port: typed questions, `Decider` (`llx decide`).
  - `history.rs`: sessions, `History`, whose `save` and `load` fail with `HistoryError`.
  - `inbox.rs`: what reaches a run between its turns, `Inbox`.
- `packages/agent`: the agent.
  - `agent.rs`: the loop: a turn's calls (those that may, at once: `calls.rs`), the inbox between turns, the stop conditions: a task ends with the model's message with no call, as Codex's does (one the output limit cut off is not one: the model goes on from it, what it thought kept as its words when it said nothing, a fourth cut in a row an error); no tool ends it and nothing invites it to stop (an answer while an agent's answer or a job is still to come waits for it); with `--schema` the data is then asked for in one more request with the `result` call forced (`schema.rs`). `Agent::run` reaches a goal in a new conversation or one that goes on (an `Option`), with the pictures attached. `Agent::context` is the app's environment block, sent before the first goal; `Agent::tell` is what the app says between goals (a changed mode), naming no tool. `agent/handling.rs`: a turn's calls carried out and answered; the last call of a reply the output limit cut off goes to `Tool::salvage` when its tool takes its arguments' shape, else is answered unrun (B7), and a cut reply that did nothing counts toward the cuts in a row. `agent/advice.rs`: the advisor's word (C9): a fresh conversation's level (kept in the `Conversation`, so a follow-up and a fork keep it); a line after an answer it finds unfinished, twice a task at most, never on the last turn.
  - `observer.rs`: what a run shows as it goes: calls, results, turns.
  - `conversation.rs`: messages that only grow. Open calls are closed; `truncate` for a rewind. A picture stays only when the person attached it.
  - `history.rs`: how a conversation is prepared before each request, a `Strategy` the app chooses (it uses `Pipeline`: stages `outputs`, `arguments`, behind a 90%→60% gate of the model's limit, a protected tail, elisions that stay: made for the prompt cache). `history_tests.rs` simulates a 300-turn dialogue.
  - `schema.rs`: the `result` call of `--schema`: `data` matching the schema, asked for after the answer with the call forced, checked, a mismatch sent back twice at most.
  - `prompt.md`: the system prompt.
  - `fakes.rs`: test-only fakes: a scripted chat, an echo tool, a recorder, and `Keep`, the history strategy that sends a conversation as it is.
- `packages/tools`: the tools, a module each.
  - `workspace.rs`: where paths resolve. A file can be read anywhere but the paths the app denies (its config directory with the keys and tokens, its sessions). Its commands run with the client's environment when it has one (`with_env`).
  - `fs/`: `patch.rs` with `patch/` (`apply_patch`: `tool.rs` the tool and its grammar, `run.rs` every file worked out and asked of the gate before any is written, a read-only verdict refused, `cut.rs` a patch the output limit cut off: the files before the one the cut fell in, applied as a patch of their own (B7), `apply.rs` and `seek.rs` a hunk found by its lines and those around it, else the file's nearest lines given back), `atomic.rs` (a write as a temporary file renamed, line endings and permissions kept), `diff.rs` (what a patch's edits did, as `patch/apply.rs` records them, rendered for the person), `picture.rs` (the one reader of PNG, JPEG, GIF and WebP: known by their signature, measured from their header, as a model takes them; the app's attachments).
  - `shell/`: `bash.rs` (the tool), `sandbox.rs` (`Scope { Open, Workspace, ReadOnly }`, from a gate's verdict by `Scope::of`; `permit`, which asks again as `Needs::Open` a workspace verdict where no sandbox can be set up: a confined command (B3) in the system's sandbox with a scratch `$TMPDIR` of its own, removed after, that writes the workspace but its `.git` in the workspace's scope (read-only where the workspace is the home or holds it, and on Linux where it has a `.git`); a read-only one refused where none can be set up; `refused`, whether a failure looks like the sandbox's, which `bash` then says) with `sandbox/macos.rs` (Seatbelt: `sandbox-exec` with a profile closed by default) and `sandbox/linux.rs` (Landlock and a seccomp filter that refuses every socket, set between fork and exec after `no_new_privs`), `process.rs` (`scoped`: the command ready to start, with the variables a command runs with (the workspace's, the client's, else the process's, less the hidden ones), then under `Quiet::On` `AGENT=1`, `NO_COLOR=1`, `TERM=dumb`, `GIT_TERMINAL_PROMPT=0` and `cat` as the pager (`GIT_PAGER`, `PAGER`), with `FORCE_COLOR` and `CLICOLOR_FORCE` dropped, then a confined command's scratch `TMPDIR` last; its own session with no terminal, a deadline, a stop, stdout and stderr one pipe read on a thread, the group killed, then the rest of the session), `query.rs` (`query`: a short command the app runs for itself, `/diff`'s `git` and `doctor`'s shell, its stdout once it exited well; killed with all it started at its deadline (R10); `Unanswered` says why there is no answer), `sweep.rs` (every process of a session killed by its session id, on macOS listed into a table on the stack, on Linux the numbered entries of `/proc`; called from ordinary threads only), `leaders.rs` (the sessions running, listed from spawn until its command's run ends, for `kill_all` when the process must quit at once), `inherit.rs` (`streams_only`: what a command inherits of llx, its standard streams and no other descriptor, every one above stderr marked close-on-exec between fork and exec; for `bash`, monitors and the daemon) and `output.rs` (what the model reads of the stream: a repeated line once with its count, a line past 2,000 characters shortened, 16,000 characters from the start and 64,000 from the end of a command that succeeded, 8,000 and 32,000 of one that failed) with `output/render.rs` (the bytes as a terminal shows them: escapes out, `\r` and backspace applied, a line past 64 KiB in pieces), `output/shown.rs` (the window as the model reads it once the command ended: the start, the cut and the command that reads it, the end) and `output/spill.rs` (the whole output, once something is left out, in `$TMPDIR/llx-output-<uid>/`: 0700, files 0600, a day and 512 MiB at most).
  - `ask.rs`: `AskTool`, the agent's `ask`: one to three questions, each with its header and its options' previews, read leniently, answered through `Person`; the answers shown to the person as question → answer.
  - `testing.rs`: test-only: temporary directories, and a gate that records what it is asked.
- `packages/providers/`: the models' providers, a package each, told who calls them (`App`).
  - `kit/`: what they share, with no port: `http.rs` (`Http`, a POST answered with a status and a body, a failure unsent only when it came before a byte went out; `Web` on the OS's TLS, its agent kept inside the kit, each post held to the request's deadline (ureq's per-request `timeout_global`), and `retry` sleeps no pause past it; `Web::get`, the catalog's GET, its answer read as a post's; forms and queries), `oauth.rs` (PKCE, random state, a pasted redirect, a token's claims, opening the system browser), `loopback.rs` (the sign-in callback on 127.0.0.1: route and `state` checked, `/cancel` to give way), `page.rs` (the browser's success and failure pages), `store.rs` (credential files, 0600; a pasted key read, a key masked for showing), `sse.rs` (server-sent events, read as an iterator), `retry.rs` (a request asked again when a wait may mend its answer, never one that went out unanswered unless the caller's `Resend` says once), `cache.rs` (the prompt cache's key: a hash of the words one conversation's requests start with).

  - `openrouter/`: `chat.rs` (chat completions, tool calling; OpenRouter's `reasoning`, cost, prompt-cache marks and a `session_id` per conversation (its first words: its logs' sessions, and the host its cache is on), or `reasoning_effort` for any other OpenAI-compatible host, and OpenAI's own API the prompt cache's key per conversation (the `session_id`'s) and the output limit as `max_completion_tokens`; OpenRouter asked to stream), `stream.rs` (a streamed completion put back together as one sent whole: a cut call keeps what it wrote, an error midway is the answer), `cut.rs` (a cut text tool's call: the string its JSON stopped in closed, B7), `system_one.rs` (the decision models), `client.rs` (OpenRouter, or any address the catalog gives; OpenRouter told the app, `HTTP-Referer` and `X-OpenRouter-Title`; the kit's `retry`: a timed-out request is not sent again, but a decision is, once), `auth.rs` (the OpenRouter key's variable, its credentials path and the PKCE sign-in; saving a key is `Provider::save_key`, for every provider).
  - `openai/`: a ChatGPT sign-in: `auth.rs` (the OAuth flow: authorize, exchange, refresh), `tokens.rs` (the tokens, the account id from their claims, `openai.json`, no ID token kept; `Saved`, where a refresh keeps them), `responses.rs` (the chat port over the ChatGPT backend's Responses API, streamed; each conversation a session of its own at the backend (`session-id` and the prompt cache's key, from its first words), so sessions and agents reach their own cache and no one machine takes them all; its own clients (600 s, 300 s idle; the token endpoint's at 60 s, `auth::issuer`, which the sign-in's exchange uses too); refresh before expiry and once on 401, held to the request's deadline, a refresh that cannot be saved logged; a stream cut off sent once more, a content-filtered reply an error), `responses/offer.rs` (the tools as the backend takes them: `apply_patch` a custom tool held to its Lark grammar where the catalog says the model takes one (`Texts`), else a function), `responses/route.rs` (sticky routing: the `x-codex-turn-state` a task's first reply names, kept by the session and `Request::task` and sent back with the task's later requests so they reach the machine that holds its cache), `responses/request.rs` (the request body: the conversation as input items, the tools, the level, the prompt cache's key), and the test-only `testing.rs` (tokens shaped as the issuer shapes them, an HTTP fake that answers from a script and records what was sent).
  - A new provider is a package here implementing `Chat` (and `Decider` where it has decision models) with a catalog, and one arm per `match` in `apps/server/src/providers.rs`.
- `packages/protocol`: what the interface and the server say to each other (ARCHITECTURE.md W1-W8), wire types only, no workspace package: `event.rs` (`Event`: what happened in a session; a call's `Label` and `Outcome`), `asked.rs` (`Asked`: a question for the person, a choice's rows in optional `Group`s; `Reply`), `command.rs` (`Command`: what the interface asks of the server, `Done`; `Place`, where a client is: its directory and environment, given at `Initialize`), `frame.rs` (`ToClient`, `ToServer`: every frame, `resource/verb` named, the same in process and over a socket; an event's `seq`, `Gap`).
- `packages/client`: the interface's side of the seam: `Client` (`in_process` over channels; `connect`, over a socket in `socket.rs`: a frame per JSON line, a writer thread, the same reader loop), `call` waits for what a command came to (`CallError`: gone, timeout, failed), `send`, `reply`; every other frame goes to the interface as it comes. Only `protocol`. `place.rs`: `here`, where this process is, as the interface says it at its handshake.
- `packages/queue`: one queue for what reaches a run from outside its own calls: entries with their own policy (whether a running task takes one, and what becomes of it while none runs: `Idle::Opens`, which waits for the next task when nothing opens it, or `Drops`), bounded, rendered as tagged data. - `packages/session`: a history store: sessions as JSON files.
- `apps/server`: the composition root, package `server`, its library `llx` (the log's targets and `RUST_LOG=llx=debug` name its modules). `lib.rs` its root; `commands`, `daemon`, `error`, `interrupt` and `output` are what the binary reaches. With the `testing` feature (only `apps/cli`'s dev-dependencies turn it on), `test_support.rs` too.

## Rules

Layers (checked by `apps/cli/tests/suite/repo/architecture.rs`):

- L1: `contracts` depends on no workspace package.
- L2: `agent` depends only on `contracts`.
- L3: tools and stores (every other package under `packages/`) depend only on `contracts`; primitives the app composes (`queue`) on no workspace package; providers (under `packages/providers/`) only on `contracts` and the provider kit, which depends on no workspace package. A tool knows nothing of the agent, the models or the other tools. A provider knows nothing of tools or of the other providers.
- L4: only apps compose packages. Only the binary (`apps/cli`) depends on apps: the server and the interface (its tests list the two again, with their `testing` features); nothing else depends on an app.
- L5: `contracts` and `agent` name no tool or provider: no browser, page, URL, OpenRouter, OpenAI, model name. The agent learns what a tool's world is like through `ToolSpec::description`. Where the run happens (the directory, the system, the mode) reaches the agent through the app's context.

Behaviour:

- A tool asks the `Gate` before an effect outside the conversation: a changed file, a command. The `Effect` summary is one line the person can judge, and it leaves nothing out (the whole command, the directory it runs in). A `Deny` goes back to the model as a failed call with its reason. Only the app answers the gate (`apps/server/src/mode.rs` and `gate.rs`); a tool never decides its own approval. A `ReadOnly` verdict runs the command in the system's sandbox, where it can change nothing, and refuses it where there is none (B3).
- A tool asks the person only through `Person`; only the app answers it (`apps/server/src/server/asking.rs`), never in `exec`. A mode is a named set of rules (ARCHITECTURE.md K5): it changes only what the gate answers and the context's `Mode:` text, never filters tools, and no code branches on its name. Rules come from the command line and the person's settings, never from the repository.
- A path the model wrote (a command's `workdir`) goes through `Workspace::readable`. Never open one without it.
- Tool content (files, command output) is untrusted data. Never let it reach a request as an instruction; mark it so where the agent reads it.
- No task- or site-specific wording in the agent's prompt or the tool descriptions. A rule earns its place by the evals, and stays general.
- Synchronous code: threads where needed, no async runtime. Tools, gates, the chat model and the person are `Send + Sync`: a turn's calls and the agents run on threads.
- The release binary stays small (under 4 MB). No dependency that is not already in the tree unless it earns its size; std first. Check `scripts/check --only size` after adding one: it fails above 5 MiB (CI's size job runs it) and warns above 4 MB.
- Exit codes (`apps/server/src/exit.rs`) and the `--json` events (`apps/server/src/output/json.rs`, `SCHEMA` in `output.rs`) are a public contract. Change them only with a schema bump and a CHANGELOG entry.

Code:

- Unit tests live beside the code, never inside it: `x.rs` ends with `#[cfg(test)] #[path = "x_tests.rs"] mod tests;` (checked by the architecture test). Fake the ports (a scripted `Chat`, a `Gate`, a `Decider`, a `View`) instead of calling a network.
- One module layout (ARCHITECTURE.md S6): a module with children is `x.rs` beside its directory `x/`, never `x/mod.rs` (clippy's `mod_module_files`). The integration tests keep `tests/common/mod.rs` and `tests/suite/mod.rs`, as cargo needs: a `tests/x.rs` is a test binary of its own.
- Every file holds at most 300 lines of working code (ARCHITECTURE.md S1, checked by `budget.rs`): a file about to pass it is split by what it does first. rustfmt defaults. Comments explain why.
- The workspace's lints are hard (`Cargo.toml`, `clippy.toml`; ARCHITECTURE.md S4): no `unwrap`, `expect`, `panic!` or `unreachable!` in working code, no prints outside the output, no `process::exit` but in `main.rs`, no `Rc`/`Cell`/`RefCell`, functions at most 100 lines, `pub` only across crates. Our own enums are matched exhaustively, no `_` arm (S10); a struct's fields are all bare `pub` or none, another crate reading a private one through a method (P3); `write!` into a String, not `push_str(&format!(..))`; a default built lazily (`unwrap_or_else`, `map_or_else`); `clone_from` over a value already there; `sort_unstable` for primitives; a parameter only read is borrowed; a method returning a changed copy is `#[must_use]`; no dependency left unused (the clippy checks). Never turn a lint off in `Cargo.toml` or for a whole module to get a change through: handle the case; the exception is an `#[expect(lint, reason = "...")]` on the smallest item, never an `#[allow]` (an exception that no longer applies fails the build); one that fires on one system or build only goes under `cfg_attr`, and a foreign enum's `_` arm names the enum in its reason. `unsafe` only in `tools` and the apps (S5).
- The project stays under 50,000 lines of working code (`apps/cli/tests/suite/repo/budget.rs`; build scripts count; tests, comments and blanks do not). This is the maximum. New code is paid for first by cutting or simplifying existing code. If a change still cannot fit, stop and ask the owner before going over: say how many lines it needs, what was already cut, why the rest cannot be, and the alternatives. Never raise the limit on your own.
- English only, in code, comments and docs.

## Tests first (TDD)

Every change is red, green, refactor:

- A bug: first a test that reproduces it, at the layer where a person meets it, run and seen failing for the right reason; then the fix; then the test passes. The red run is the proof the test can fail: never break working code to get one.
- A feature or a change of behaviour: its tests first, written from what a person does and sees (keys pressed, the screen, what the model was sent), then the code.
- Refactor only on green. A test that cannot fail, or that restates a text or a constant, is deleted, not kept.

The layers:

- unit tests beside the code (`x_tests.rs`), with the ports faked;
- screen tests in the crate: the `App` driven by keys and events and drawn into a `vt100` screen (`apps/tui/src/test_support.rs`), asserting what the screen shows, never the app's fields;
- one integration binary, `apps/cli/tests/all.rs` (`common/` for the harness, `suite/` for the tests): the real binary against a scripted model server that keeps every request (assert what the model received), and pty flows in `suite/tui/` that press keys and read the screen as a person does.

## Checks

`scripts/check` is the one entry point, and the same commands run everywhere: by hand, in the git hooks, in Claude Code's Stop hook, and in CI (each step of `.github/workflows/ci.yml` is `scripts/check --only NAME`). It prints a plan (each check, its scope, why), runs it in one fixed order, stops at the first failure with that check's output, and ends with one summary line; exit 0, 1, or 2 for a usage error. `scripts/check --list` names the checks, `--plan` prints the plan for the paths on stdin.

What runs when:

- Before you say a change is done: `scripts/check`. The checks the branch's change needs: everything changed since the merge base with main, plus the working tree (staged, unstaged, untracked).
- When a Claude Code agent ends its turn: `scripts/check --fast` (`scripts/hooks/claude-stop`, in `.claude/settings.json`), only when the working tree changed since a check last saw it (a stamp in `target/llx-check/`), so an unchanged tree costs nothing. A failure blocks the stop with its output; the same failing tree is let through the second time, with a note. It changes no file and stops after 240 s. `LLX_STOP_CHECK=off` turns it off.
- `git commit`: `scripts/check --fast --staged` on what the commit stages (a staged file with unstaged edits is refused: the checks read the working tree). `git push`: `scripts/check --fast` on what is pushed (since the remote's commit), in seconds; the tests, the size and the site run in CI, and by hand with `scripts/check` before a change is called done. Install both once with `scripts/setup` (`git config core.hooksPath scripts/hooks`); `--no-verify` skips them.
- CI: every check but `coverage`, a job for each group (`check`, `size`, `site`, `action`). `scripts/check --all` runs the same set locally, in CI's order; add `--coverage` before a release.

The plan comes from the changed paths alone (`scripts/checks/plan.awk`, with an example of each rule in `scripts/checks/check_test.sh`): a crate's directory brings `fmt`, `clippy` and `test` for the crate and its dependents (cargo metadata's graph; `--fast`: clippy on the crate alone); the root `Cargo.toml`, `Cargo.lock`, `clippy.toml` or `rust-toolchain.toml` the same for the workspace; a manifest, the lock or the toolchain the release `size`; anything the repository's rules (`repo`: `suite::repo`, unless the tests run them); `site/`, `docs/` or `examples/README.md` the `site` build; `action.yml` or `action/` the `action` tests; `scripts/check` or `scripts/checks/` the checks' own tests (`check-test`); a shell script `shellcheck`; a workflow, `action.yml` or an example `actionlint`, and an example the `examples` conventions; Markdown, or a path gone, `mdlinks` (relative links and anchors); anything, `secrets` (gitleaks on every commit and on what the index and the working tree change; a finding known to be fake goes in `.gitleaksignore` by its fingerprint). `--fast` leaves out the tests, the size and the site. The linters are pinned (shellcheck, actionlint, yq, jq, gitleaks in `scripts/checks/tools.sh`): downloaded once into `~/.cache/llx/tools`, each checked against its SHA-256, never the one on the PATH.

Ratchets: the line budget and the 300-line files (`budget.rs`), the `expect`s in working code, which only fall (`code.rs`, S4), the coverage floor (`scripts/coverage.sh`), and the binary's cap (`size`: fails above 5 MiB, warns above 4 MB).

What the checks run (`scripts/checks/run.sh`), and the rest by hand:

```bash
cargo fmt --all --check                                       # fmt
cargo clippy --workspace --all-targets -- -D warnings          # clippy
cargo clippy --workspace --lib --bins -- -D warnings -D unused_crate_dependencies  # then: no dependency unused (tests left out)
cargo test --workspace            # test: unit tests, apps/cli/tests/all.rs (the binary, the layer rules)
cargo test -p llx --test all -- suite::repo::                  # repo: the repository's rules alone
```
